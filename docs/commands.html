Masks#

/mask#mask.py

Build a mask from that run's own detector image

FormWhat it does
/mask createBuild a mask from that run's own detector image
/mask listMasks discoverable from here
/mask create 186636 --dry-run
/mask create 186636 --leak
/mask list
Full in-CLI help
/mask create <run> [options]   build a mask from a run's own detector image
/mask list                     masks discoverable from here

Use a uniformly illuminated run — banjo, flood or empty cell — and check the
_compare.png it writes. Three things are masked: the beam stop, the
low-response bands at both tube ends, and deviant tubes. The run number
alone is enough; the archive is searched for it, so /load ipts is not needed.

Common
  --dry-run              report and preview only, write no mask file
  --leak                 also mask direct beam that fell past the stop under
                         gravity (always reported; masked only if you ask)
  --tubes <a,b,c>        mask these tubes as well — auto-detection is
                         whole-tube, so a dead segment averages out
  --disc <x>,<y>,<r>     mask a disc, in mm. Repeatable; adds to the rest

Beam stop  — sized from a horizontal cut through it: the valley between
the flare walls is the stop's diameter. Runs with no flare are sized from the
shadow instead. Every mask prints the measurement, scale and pad behind its
radius, and the mask is meant to be wider than the visibly dark disc — the
ring outside that is penumbra, where the stop still blocks part of the beam.
  --beam-scale <f>       grow the measured radius (default 1.0 measured,
                         1.2 from a shadow); --beam-pad <f> adds y-pixels
  --beam-center <x>,<y>  state the centre in mm, skipping detection
  --beam-radius <mm>     state the radius in mm, used verbatim
  --no-beam              do not mask the beam stop
  --leak-scale <f>       grow the leak discs (implies --leak); 1.3-1.5 takes
                         the faint tail below the broad peak

Tube ends and tubes
  --top <n> / --bottom <n>  how MANY pixels to mask at each end, not indices:
                         --bottom 11 masks pixels 0-10. Default: measured —
                         where response falls below half the plateau — but
                         never below the 11-pixel EQSANS convention, which in
                         practice is what applies. An explicit value wins, so
                         --top 0 --bottom 0 turns the bands off. --bottom is
                         the low-index end — the machine-physics mask tool
                         names these the other way round.
  --tube-sigma <f>       flag tubes more readily, lower is looser (default 5)
  --no-tubes             skip tube detection

Elsewhere
  --ipts <n>             skip the archive search, or disambiguate
  --outdir <dir>         where to write (default: here, which is what makes
                         the mask discoverable)

Coordinates are millimetres from the detector centre, +y up, face
x -525..525 and y -521..521 — so --disc 13,-55,48 is 13 mm to one side and
55 mm BELOW centre. Not pixels: tube index is not a spatial coordinate. The
preview carries mm on the bottom and left, tube and pixel index on the top
and right, so either can be read straight off it.

Examples
  /mask create 186104 --dry-run               look before writing
  /mask create 186636 --leak                  add the gravity-dropped beam
  /mask create 186104 --tubes 146             add a known-bad tube
  /mask create 186104 --beam-radius 30        state the stop yourself
  /mask create 186636 --disc 13,-55,60        one disc, your own size

If it looks wrong, open the _compare.png:
  beam mask off-centre   run too dim — use a brighter one, or --beam-center
  beam mask too small    no flare walls, so the shadow was used — --beam-radius
  a bad tube missed      name it with --tubes; segments average out

Writes mask_<config>_<run>.nxs, a _compare.png and a .params.json into the
current folder. The configuration in the name is what lets /matchruns and
/instrument find the mask on their own. Needs drtsans, like /reduce.

Full in-CLI help
Usage: /autopilot <ipts_number> [options]
  /autopilot 35884                              — Full automated reduction
  /autopilot current                            — Use current IPTS/catalog from session
  /autopilot 35884 --continue                   — Reduce only NEW runs (reuse saved calibration)
  /autopilot --continue                         — Continue from saved session in outputdir
  /autopilot current --from 5                   — Start from step 5 (skip catalog/match/presets)
  /autopilot current --to 8                     — Stop after the scale factor is found+applied (steps 1–8)
  /autopilot current --from 6 --to 8            — Only the standard: reduce porsil, calibrate, apply scale
  /autopilot 35884 --standard porsilb1          — Use porsilb1 as calibration standard
  /autopilot 35884 --samples Bi1                — Only reduce Bi1 samples
  /autopilot 35884 --exclude Y5                 — Reduce all except Y5
  /autopilot 35884 --thickness 0.2              — Set thickness to 0.2 cm
  /autopilot 35884 --bkg banjo                  — Use banjo as background
  /autopilot 35884 --config 8m12a               — Reduce only 8m12a config
  /autopilot 35884 --exclude Y5 --bkg emptyticell --thickness 0.15  — Combined
  /autopilot 35884 --force                      — Re-reduce all (ignore done status)
  /autopilot 35884 --fresh                      — Force reload of catalog + re-match table (ignore in-memory state)

Autopilot steps (13 total):
   1. Load catalog from ONCat
   2. Match runs (build working table: trans/bkg/empty assignments)
   3. Verify assignments
   4. Apply presets to each configuration
   5. Set output directory
   6. Reduce standard sample (porsil, scale=1.0)
   7. Calibrate absolute scale factors from standard
   8. Apply scale factors to each config
   9. Reduce all sample runs
  10. Build stitch table
  11. Smart overlap analysis
  12. Stitch profiles
  13. Plot results

--from N: skip steps 1..(N-1) and start at step N. Requires catalog + working
  table already in session (e.g. from prior /load ipts + /matchruns + /apply preset).
  Examples:
    --from 5  — skip load/match/verify/presets; set outputdir and proceed to porsil
                (use when match table + configs are already set up the way you want)
    --from 6  — skip outputdir too; jump straight to porsil reduction
    --from 9  — skip standard/calibrate/apply-scale; reduce samples with existing scales
    --from 10 — only stitch and plot (reductions are already done)
    --from 13 — only plot
  Cannot be combined with --continue.

--to N (aliases --till, --until): stop after step N completes; write a
  resumable summary and save the session. Combine with --from for a window.
    --to 2   — just build the working table, then stop
    --to 8   — reduce the standard, calibrate and apply the scale factor, then
               stop before reducing samples ("find the scale factor")
    --to 9   — reduce everything but skip stitch + plot
  Grouped steps stop as a block: --to 6/7 run through 8 (scale calibration),
  --to 10/11 run through 12 (stitch). Resume later with --from or --continue.
